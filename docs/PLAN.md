# Minecraft 动态背景音乐模组 (Dynamic BGM Mod) 计划书

本计划书旨在设计一个对标并超越 Minecraft 原生背景音乐系统（BGM Manager）的自定义音乐播放模组。该模组支持**本地**、**服务器**和**第三方平台**三大音乐曲库，提供强大的动态环境音乐触发引擎，并以 `Alt+M` 快捷键作为核心控制面板的入口。

---

## 1. 核心定位与设计目标

### 1.1 对标原生背景音乐系统
Minecraft 的原生背景音乐（由 `MusicTracker` 控制）是随机且间隔较长的，只根据**维度**或**特定生物群系**播放固定曲目，缺乏即时反馈感 and 个性化配置。
本模组的核心目标是：
- **无缝接管/替换原生 BGM 播放器**：提供平滑的淡入淡出（Cross-fading）切换，避免音乐突变。
- **高自由度规则配置**：玩家和服务器主可以自定义“在什么情况下，播放什么音乐”。
- **多音源融合**：打破游戏内资源包（Resource Pack）的限制，直接支持外部音频文件、流媒体和网络接口。

### 1.2 快捷键与交互设计 (`Alt+M`)
- **核心快捷键**：`Alt+M`
  - **单次按下**：打开/关闭模组主 UI 面板（包括音乐库浏览器、播放列表、设置等）。
  - **双击/组合键（可配置）**：
    - `Alt+Up/Down`：调节本模组独立音量。
    - `Alt+Space`：暂停/恢复播放。

## 2. 功能架构设计

- **本地音乐曲库 (Local Music Library)**：
  - 存储路径：客户端目录下自动创建 `.minecraft/dynamic_music/local/` 文件夹。
  - 音频格式：原生支持 `OGG`, `WAV`（通过 OpenAL 直接解码），集成 `JLayer` 等库解码支持 `MP3`, `FLAC`。
- **服务器音乐曲库 (Server Music Library)**：
  - 下载缓存模式：在服务器配置文件中定义曲目列表及 URL，客户端连接时在后台下载并缓存至 `server_cache/`，播放时直接读取本地缓存。
  - 实时流媒体模式：直接流式传输音频，适合特定交互物品（如点歌机）。
- **平台曲库播放 (Platform Music Library)**：
  - 网易云音乐/QQ音乐：支持搜索歌曲、导入歌单、展示每日推荐和扫码登录（展示在游戏内 UI）。
  - 自定义网络流：支持挂载个人 WebDAV/NAS 音频流。

---

## 3. MC 背景音乐对标与触发引擎 (AmbientMusicEngine)

模组将监控游戏状态并动态切换曲目：
- **Boss 战 (Boss Fight)**：出现 Boss 血条时立即渐变切歌（优先级：1）。
- **战斗状态 (Combat State)**：玩家受到攻击或连续攻击敌对生物时播放战斗 BGM（优先级：2）。
- **特殊维度 (Dimension)**：主世界/地狱/末地/Mod 维度等对应不同歌单（优先级：3）。
- **生物群系 (Biome)**：根据沙漠、海洋、樱花林等播放相应风格曲目（优先级：4）。
- **游戏时间 (Time of Day)**：白天轻快，夜晚舒缓（优先级：5）。
- **淡入淡出 (Cross-fading)**：正在播放的歌曲音量在 2~3 秒内淡出至 0，新歌音量从 0 渐变升至目标音量，避免声音突变。

## 4. UI/UX 界面设计规划

模组 UI 采用现代 **玻璃拟态 (Glassmorphism)** 风格：
- **主播放界面 (Alt+M Panel)**：
  - **左侧**：导航栏（本地/服务器/平台曲库/环境触发规则/设置）。
  - **中间**：歌曲列表浏览器（支持搜索、排序）。
  - **底部**：播放状态条（歌曲封面、歌名、歌手、播放/暂停、随机/循环模式切换、进度条、音量条）。
- **悬浮窗 HUD**：新歌播放时在屏幕边缘滑出“正在播放：xx - xx”提示框，并可在屏幕边缘显示实时滚动歌词。

## 5. 项目开发路线图 (Development Roadmap)

### 阶段一：基础架构与本地播放 (Milestone 1) - **已完成**
- [x] 搭建 Multi-loader 开发环境，支持 **Minecraft 26.1.x**、NeoForge 及 Fabric。
- [x] 注册 `Alt+M` 快捷键并实现基本的按键输入监听。
- [x] 编写 `CustomMusicManager`、`AmbientMusicEngine` 基础类骨架。
- [x] 创建本地多语言翻译文件 (`en_us.json`, `zh_cn.json`)。

### 阶段二：服务器同步与规则触发 (Milestone 2) - **已完成**
- [x] 编写环境监测 tick 逻辑，实现根据维度、群系动态自动切歌。
- [x] 整合 `JLayer` 及 Java Sound SPI，支持本地 MP3、OGG、WAV 文件的解析与多线程解码播放。
- [x] 编写淡入淡出（Cross-fading）渐变线程，支持平滑声效过渡。
- [x] 基于 Fabric / NeoForge 平台网络数据包 API 注册自定义数据包 `PlayMusicPayload`，实现服务端控制客户端播放。
- [x] 编写 Mixin 注入原版 `MusicManager.tick()`，在自定义音乐播放时自动禁用原版 BGM 播放器。

### 阶段三：三方平台对接与高级 UI (Milestone 3) - **已完成**
- [x] 编写 `PlatformMusicApi` 类，支持第三方流媒体搜索与播放接口。
- [x] 设计开发了现代**玻璃拟态**风格的 UI 控制面板 `MusicPlayerScreen`，显示歌曲标题、歌手、当前状态与播放队列。
- [x] 实现了交互式音量调节滑块（支持鼠标点击及拖曳修改音量，UI 实时百分比和进度控制同步显示）。
- [x] 支持本地文件夹自动文件扫描与播放列表播放，实现真正的音乐轮播播放与切换。

### 阶段四：播放控制升级与热重载管理 (Milestone 4) - **开发中**
- [ ] **播放模式控制**：引入 `SEQUENTIAL`, `LOOP_ALL`, `LOOP_ONE`, `SHUFFLE` 状态机，UI 增加对应控制按钮图案。
- [ ] **热重载监听机制**：利用 `java.nio.file.WatchService` 启动后台守护线程，对 `.minecraft/dynamic_music/local/` 目录变动（创建、删除、修改）实现毫秒级 UI 即时刷新。
- [ ] **文件导入器**：新增导入按钮，集成 LWJGL `TinyFileDialogs` 打开系统原生文件选择窗口，支持多选并直接拷贝至本地曲库。

### 阶段五：双端分离与云端/第三方平台流媒体对接 (Milestone 5) - **待启动**
- [ ] **架构深层解耦**：客户端区分独立运行与联机模式，彻底分离本地缓存 (`LocalLibrary`) 与服务端下发缓存 (`ServerLibrary`)。单机/纯净服模式下仅激活 Local UI。
- [ ] **服务端音乐上传分发**：新增客户端上传界面，基于安全鉴权（仅限 OP 等权限），将音频文件通过 32KB `ChunkPayload` 分片切包上传至服务端。服务端广播通知全服拉取。
- [ ] **国产流媒体巨头直连解析**：原生接入网易云音乐、QQ音乐、酷我音乐、酷狗音乐 API。实现扫码登录、搜索接口对接，无缝提取免 DRM 音轨并直接推送至 Lavaplayer 解码。
- [ ] **Spotify/Apple Music 元数据对接机制**：由于强 DRM 限制不直接解码其音频流，而采用 OAuth 授权登录获取个人歌单元数据列表（歌手+歌名），静默后台转由开放音源（如 YouTube/网易云 等）进行无感替代解析与播放。
